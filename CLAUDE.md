# Toiletry Shelf Game

Three.js + cannon-es physics game (Vite, vanilla JS, no framework). Player drags toiletries off a shelf, packs them into plastic bags, and decorates finished bags with hand-drawn gift tags.

## Run it

```
npm install
npm run dev      # http://localhost:5173 (or next free port)
npm run build     # outputs to dist/
```

## Architecture

- `main.js` — wiring + the fixed-timestep loop. Owns `spawnItem()`/`despawnItem()` and a **slot registry** (one entry per shelf position, holding the item currently in it). Items are created and destroyed mid-game, so anything that caches an item list must tolerate that — push/splice the shared `pickables`/`pairs`/`trackedItems` arrays rather than rebuilding them.
- `layout.js` — pure data (shelf/table/room dimensions, item templates). No dependencies; shared by physics and rendering. An item's `shape` is `'cylinder'`, `'box'`, or `'compound'` — a set of boxes welded at fixed offsets into one body (the toothbrush + toothpaste). A compound's `size` is its overall bounds, used for shelf packing; `buildItems()` throws "Shelf N is overfull" if a resize stops a row fitting, which is the cheapest check that a size change is safe.
- `physics.js` — cannon-es world setup, static colliders, `createItemBody()`. Items use `linearFactor: (1,1,0)` / `angularFactor: (0,0,1)` — **every pickable item is locked to one Z-depth plane** so nothing can roll out of a bag's reach. Preserve this on any new item type.
- `scene.js` — Three.js renderer/camera/lighting, static meshes, per-item-kind mesh builders. Also owns the **ink outline**: `INK` is one pen width (3.6mm) for the whole scene, and `outline()` gives a mesh an inverted hull (a black `BackSide` shell of the same geometry, scaled per-axis so the line keeps an even weight). `createItemMesh()` applies it to every part of every item, so a new item kind is inked by default. `inkBoxMesh(mesh, scale)` inks one box on all 12 edges in its own space (used by the bag and tag stacks on the shelf, which are rotated and, for tags, scaled 1.6x). The clamp matters — no shell may grow a part by more than a tenth of its own narrowest dimension, or a 3.6mm line round a 5.5mm toothpaste neck swells it wider than the cap in front of it. The shelf and table don't use the hull: `inkBoxEdges()` draws all 12 edges of every furniture box as pen-width bars merged into one mesh, because a hull only traces silhouettes and left no line down the corner of a leg seen at an angle.
- `drag.js` — the core pickup mechanic: a cannon-es Spring between the held body and a cursor-following anchor. Tuned via `STIFFNESS_PER_KG`/`DAMPING_PER_KG` — don't retune without a reason, other systems (bag handle, tag) mirror this tuning intentionally for a consistent feel.
- `interaction.js` — raycast pickup/hover. Supports two paths: a plain mesh with `userData.body` uses the standard spring drag; a mesh with `userData.onGrab` hands control to a custom controller (used by soft bags and the tag/bag generators). If `onGrab` returns nothing, no drag starts — that's how generators intercept a click as "open a UI" instead of "pick me up." A third flag, `userData.locked`, blocks grabbing entirely while leaving the mesh hoverable, so bagged items keep their name label.
- `softBodyBag.js` / `bags.js` — plastic bags: a ~9-particle mass-spring "soft body" while carried, snapping into a single static rigid body when dropped on the table. `bags.js` tracks per-bag contents/completeness and the checkmark, and owns the seal/lock rules below.
  - **Shape comes from one function.** `shapeBag(u, v, w, swell, t)` maps the unit cube onto the bag; `deform()` then maps those stored coordinates through the 8 particles. `t` morphs the profile: **0 is the plain box the bag is carried and packed in, 1 is the cinched pouch it shrivels into when finished.** Both poses are baked once per shell and cross-faded by `setShrivel()`, so changing shape costs a lerp per vertex, not a regenerated profile.
  - `bagHalfExtents(v)` exports that profile. **Anything positioning itself against a bag asks it rather than assuming `BAG.width`/`BAG.depth`** — the film bulges ~45% past nominal at the belly and cinches to a quarter of it at the neck. The gift tag and `MIN_BAG_GAP` both derive from it.
  - The bag's **ink outline is its edges drawn as lines** — 4 vertical seams, a ring round the base, a ring round the mouth, plus the 2 outer profiles — not a filled silhouette. Each is a quad strip billboarded to face the camera (see the gotchas for why it can't be a hull and can't be a GL line).
- `softRag.js` — washrags as a floppy particle chain (same idea, simpler). Exposes `reset`/`push`/`lock`/`placeAt`/`dispose` so the restock button and the tidy-up can treat a six-particle rag like any other single-body item.
- `restock.js` — the bottom-left Restock button: returns loose items to their slots, spawns replacements for bagged ones, cleans up orphans, and disposes any bag still `soft` (dropped anywhere but the table) via `bags.clearStrays()`. A bag in hand and every placed bag are left alone.
- `homeButton.js` — the top-left Main Menu button, created in `bootGame()`. It returns to the menu by **reloading the page** (after an in-game confirm card styled like the Settings panel — never `window.confirm()`, which renders as the browser's own dialog), not by tearing the game down: `bootGame()` builds its renderer, world, listeners and HUD with no teardown path, so a reload is the only return that leaves nothing behind. Achievements and settings persist through it via localStorage; bags don't. An in-place return would need a real `bootGame()` teardown first.
- `milestone.js` — every `MILESTONE_BAGS` (5) finished bags — at 5, 10, 15... — a "Congrats! You filled N bags!" line and two cards pop up side by side: a donation QR code (left) and a volunteer link (right). Triggered from `bags`' `onFinish` in `main.js`, right after the counter bumps. At exactly `BADGE_BAGS` (15) a different card comes up *instead*: a drawn badge and "show this screen to Fill a Heart 4 Kids (FAH4K) to claim your free badge" — claimed in person, so there is nothing to redeem in code. From then on the badge sits under the heart counter as a button (`.ms-badge-btn`) that reopens the same card; like the counter, it lasts the session. Clicking the title sign on the wall opens the same two cards any time via `milestone.open()`, without the congrats line — the sign is click-only, not grabbable: its `onGrab` returns nothing, the same trick as the tag maker. **The QR and the link are placeholders** (`DONATE_QR_SEED`, `VOLUNTEER_URL` at the top of the file): the QR is drawn to look real but encodes nothing, and the link is on example.org. To test without packing five bags by hand, type `chellito` in-game (the `cheats.js` shortcut packs and tags a bag) and press Restock between bags.
- `achievements.js` — the store (persisted in localStorage), the unlock toast and the 🏆 page. Adding an entry to `ACHIEVEMENTS` is all that a new one needs on the UI side.
- `bottleFlip.js` / `throwIn.js` — the achievement watchers, one per easter egg. Each is polled from the frame loop and calls `achievements.unlock(id)`. They observe existing state (`drag.held`, `bags.holds`) rather than requiring hooks in the systems they watch.
- `tagGenerator.js` / `tagPopup.js` / `tags.js` — gift tag mechanic: click the generator to open a draw/text popup (only once some bag is complete and still untagged — until then the click does nothing and the hover label says so), finished tag becomes a normal pickable, snaps onto a completed bag and grows to `TAG_ATTACH_SCALE` as it lands. The card is a thin box, not a plane, so it matches its 8mm collider and has edges for its ink border to sit around; only the two large faces carry the drawing.
- `menu.js` — the 3D main menu shown before the game boots, fully self-contained: its own renderer, scene and overlay, all released on Play (`startMenu().then(bootGame)` in `main.js`; everything in `bootGame()` is created only after that). Clicking a balloon pops it with a synthesized sound and a confetti burst from a pooled `InstancedMesh`; the confetti lands on the table tops or floor via `groundAt()`, which mirrors `buildTables()`'s positions — move a table and update both. Popped balloons regrow after `REGROW_DELAY`. Balloons are *placed*, not scattered: `BALLOON_ROLES` gives each colour group's wanted positions, then `placeBalloons()` puts each one (biggest first) in the free spot nearest its wanted place, inside a band — under the rail (`BALLOON_CEILING`), clear of every lamp (`SPOT_XS`, shared with `buildLighting()`), above the painted heading where it runs (`HEADING_X`, `BALLOON_FLOOR`) and above the small text lines elsewhere (`BALLOON_FLOOR_SIDES`) — and never within `BALLOON_GAP` of another balloon, all measured at full regrow swell and top of bob. A balloon with no free spot is dropped, so raising `count` in a role doesn't guarantee more balloons: the band is the real limit. Repairing a random layout by pushing overlaps apart was tried and kept jamming against the lamps and band limits. A balloon may come forward of the rail only if, seen from the camera at its lowest and nearest (`EYE_Y`, `EYE_Z_MIN`), its top still passes under the rail — the camera looks up, so anything in front of the rail appears higher than it is; a flat "no further forward than the rail" rule was too strict for the big pinks to fit at all. The counts in `BALLOON_ROLES` are tuned to land 36; changing any one reshuffles the random layout for the groups after it, so re-measure. Placement runs once at menu start and costs ~150ms in Node — widening its search (±1m now) or asking for many more balloons grows that.
- `inkPass.js` — screen-space ink for the menu (`createInkRenderer`, used in place of `renderer.render`). A second render with an override material writes each pixel's normal and an object id (`object.id`, plus the instance index for instanced meshes); a full-screen pass draws a line where the id changes, the normal creases, or depth jumps. That inks every mesh with no per-object setup, which the hull can't do across hundreds of assorted menu meshes. Anything too small to survive a 2px line round it (the confetti) goes in `exclude`.
- `settings.js` — music / SFX / subtitles / reduce-motion, persisted in localStorage. `getSettings()` is the live object; read it at use time rather than caching it. Any new sound should check `getSettings().sfx`.
- `bubbles.js`, `title.js`, `hoverLabel.js` — cosmetic: intro transition, title card, hover tooltips + world-anchored labels (checkmarks etc).
  - The intro bubbles are see-through, so they're inked with a camera-facing black ring rather than a hull (see the transparency gotcha). A sphere's silhouette is exactly a circle of radius `r·√(1−r²/d²)` sitting `r²/d` in front of its centre, so `placeRing()` puts the ring there each frame — exact from any viewpoint, no projection search needed.
- `mia.js` — Mia, a Mixamo-rigged character (FBX clips in `public/models/`) who collects each finished bag: walks in from the right, reaches, lifts it, turns, carries it off frame. Visual only, no physics body. Takes the bag via `bags.takeAway(entry)` and each item via main.js's `carryAway(handle)`, which pulls it out of the simulation but leaves its mesh for her to move; she calls `destroy()`/`bag.dispose()`/`tags.disposeTag()` once off screen.
- `bagCounter.js` — the heart HUD (top-left, under the Main Menu button) counting finished bags this session; `bags` calls its `onFinish` once per bag, the frame the pouch finishes shrivelling. The heart is a button: clicking it opens a card with "You filled N bags!" and one fact scaled to N, cycling through `FACTS` on each open (a separate line when N is 0). **The facts are rough estimates** (e.g. `SHOWERS_PER_SOAP`, a bar of soap ≈ a month of daily showers), not the charity's figures — swap in real ones when available.

## Bag lifecycle

Four states, and the transitions matter more than the code makes obvious:

1. **Open** — items entering the bag are counted after settling (`SETTLE_TIME`) but stay fully dynamic and grabbable. Containment is re-checked every frame, so lifting a mistake back out un-counts it. This window is deliberately forgiving — with one exception: a second copy of a label the bag already counts is ejected (same push as `ejectIntruders`). Only *counted* items block, so two copies landing within one `SETTLE_TIME` of each other can both count.
2. **Complete** — the frame the bag holds one of every label in `required`. This is the commit point: `entry.sealed` is set, and every contained item is `lock()`ed (body → static, `userData.locked` → true). Nothing comes back out.
3. **Sealed** — contents are frozen, `trackContents` is skipped entirely, and anything lowered in afterwards is shoved back out by `ejectIntruders`. The bag is still a **box** here: that is what makes it packable, and it stays one for every stage above.
4. **Finished** — the frame a sealed bag also has a gift tag on it (`entry.complete && entry.tag`). `planTidy()` runs once and the bag spends `FINISH_DURATION` shrivelling from box to pouch while its contents stand themselves up inside it: upright, tallest along the back, all of it on the folded washrag. A single animation, so the bag looks like it is drawing the order together.
5. **Carried off** — once the shrivel is done (`bags.isFinished`), Mia comes for it. `takeAway` drops its collider, checkmark and list entry (freeing the table spot); its items are flagged `gone`, which restock treats like "still in a bag" and refills the slot.

Notes on the tidy, since they are not obvious from the code:

- Contents are **static** by this point, so placing them off the shared Z plane is safe and the layout uses two rows — one row doesn't fit, the eight rigid items are ~486mm stood side by side against a ~300mm bag. Rows are chosen by height at runtime, not hardcoded, so adding or resizing an item still works.
- Every handle (including the rag's) exposes `placeAt(pos, quat, blend)`, where `blend` is *absolute progress* 0..1 and the implementation eases from wherever it currently is. Nothing has to capture a start pose, and blend 1 lands exactly on target.
- Rows are packed to `PACK_INSET` of the bag's width, not the full width. The cross-section is rounded, so an item's **corner** sits further from the axis than its edge does, and that diagonal — not the width — is what decides whether it pokes through the film.
- `POUCH_BASE` and `GATHER_START` are tuned **together** against that clearance. Neither works alone: a fatter bag that still cinches at 58% leaves the body wash 36mm through the film, and a late cinch on a narrow bag is no better. Re-check the clearance if you retune either.

The restock button never reclaims an item from a bag at any stage — the slot gets a freshly spawned replacement instead, and an item that left a bag before it sealed is despawned on the next press so repeat presses can't accumulate duplicates.

## Gotchas

- **Mia's un-posed bind mesh lies about where her feet are.** It is centred on the origin (y ≈ −0.95…0.95 in rig units), but every clip poses her standing *on* the origin, so the root belongs at y = 0. Offsetting it from `Box3.setFromObject` on the loaded model floated her half a metre up. Measure skinned vertices after `mixer.setTime()` (`mesh.getVertexPosition`) — `Box3` ignores skinning. Two more from the same export: its material loads with a black diffuse colour and poor normals (so she uses an unlit `MeshBasicMaterial`), and each clip's hips carry baked travel and heading that disagree between clips, so `pinRoot()` strips them and the controller drives the root instead.

- **Asset URLs at runtime must use `import.meta.env.BASE_URL`, never a hardcoded absolute path.** GitHub Pages serves this from a subpath (`/Project_Dignity/`); anything built as a template string injected via `<style>`/`<script>` at runtime (not a real `.css`/`.html` file) bypasses Vite's own path rewriting. `title.js`'s font-face is the reference example — bit us once already (font silently fell back to a system font in production, worked fine locally).
- `vite.config.js`'s `base` is derived automatically from `GITHUB_REPOSITORY` at build time — don't hardcode it.
- **Scaling every item's mass by the same factor changes nothing.** Gravity is mass-independent, the drag spring is tuned per-kg (`STIFFNESS_PER_KG`), and friction scales with weight — so a uniform "make things heavier" is a pure no-op. What actually governs how far one item shoves another is the *ratio* between them; `layout.js` keeps heaviest:lightest near 4:1 for that reason. To resist toppling, reach for `angularDamping` and restitution instead.
- **A `STATIC` or `SLEEPING` body does not integrate gravity at all** (`Body.integrate` returns early on both). Anything pinned via `item.lock()` stays exactly where it is, which is the point — but it also means you must never restore a body to `SLEEPING` if it might be unsupported: sleepers are only woken by contact, so one left in mid-air hangs there permanently. Wake on unfreeze, always.
- Static/sleeping pairs are skipped by the broadphase (`needBroadphaseCollision`), so a pinned item generates no contacts — you cannot ask "is this still supported?" once it is static.
- **Mesh builders must express every dimension as a fraction of the item's collider size**, never a literal. `scene.js` builders are written this way so resizing an item in `layout.js` scales its whole appearance; a hardcoded `0.008` handle radius silently stays put while everything around it grows. Bit us once when scaling the toothbrush set.
- **Hand-built `BufferGeometry` needs its winding order checked.** `computeVertexNormals()` happily produces inward-facing normals from backwards triangles: the build passes, the geometry is valid, and the mesh just renders inside-out. `tubeBarrelGeometry` in `scene.js` had exactly this. Assert `dot(normal, outward radial) > 0` on a sample of vertices rather than eyeballing it. **`DoubleSide` hides this completely** — `softRag.js`'s ribbon was wound inside-out for all 132 triangles and nobody could tell, because a double-sided material shades a back face off the flipped normal. It only surfaced when a `BackSide` ink shell was added on top, which would have drawn its near face and painted the rag solid black. If a mesh is `DoubleSide`, its winding is untested by definition.
- **Bag dimensions get copied into other files and go stale.** One commit reshaped the bag (width 0.4→0.3, depth 0.24→0.17, height 0.24→0.36) and silently broke three things at a distance: the gift tag's attach window was anchored on the rim so it rose 12cm out of reach and tags stopped sticking; the tag's snap position landed in the cinched neck and left it floating 65mm off the bag; and the toothbrush set no longer fit through the mouth at all. Nothing warned. **Derive from `bagHalfExtents()` or from `BAG` at runtime, never copy a measurement**, and prefer a startup check that throws (see below) over a number that drifts.
- **`BAG.depth` has a hard floor set by the longest item.** Items are Z-locked with `angularFactor (0,0,1)`, so an item's Z extent is fixed however the player turns it — the toothbrush set is 209mm along Z forever. A bag shallower than that plus wall clearance is one the set *physically cannot enter*: it straddles the front and back walls and rests on top. `createBagSystem` now throws at startup naming the item and both measurements, in the spirit of "Shelf N is overfull". Depth is also the dimension the fixed front-on camera shows least, so it is the cheap one to give away.
- **A bag is taller than a shelf cubby, so inside the shelf it is folded.** A bag is 46cm with its handle and each cubby 35cm; spawned full-size on its stack it started with the rim through the board above and was dragged visibly through it. `softBodyBag.js` now shrinks the springs' vertical rest lengths to `SHELF_FOLD` whenever the bag's base is within the shelf's span (`inShelf()`), and eases back to full size (`FOLD_RATE`) once it is clear. The particles collide with the boards, so lifting straight up stops under the board; the bag leaves by the side, like items. `SHELF_FOLD` is derived from `SHELF.levels`, so re-spacing the shelves keeps it fitting.
- **An inverted hull doesn't work behind a transparent material.** The items' outline works because they are opaque: the black shell is only visible past the silhouette. The bag's film is 34% opaque with `depthWrite: false`, so a shell behind it shows straight through and blackens the whole bag instead of drawing a rim. Either mask it (redraw the film depth-only *after* the opaque contents, then depth-test the hull against it) or, as the bag now does, draw the edges as explicit geometry.
- **A silhouette depends on the shape *and* on where the camera is.** A box's on-screen silhouette is a hard corner, a round pouch's is the middle of a face, and the bag is both at different times. Worse, the table sits off to one side of the camera, so you see around the bag's inner face and its **far** edge is the one that reaches furthest that way — assuming the near half cost 32px of misalignment. If something must trace a silhouette, search for the extreme by projecting candidates through the real camera; don't reason out where the edge "should" be.
- **A GL line is capped at 1px on most hardware.** Anything that needs to read as a pen stroke has to be a quad strip billboarded to face the camera — width taken perpendicular to both the edge direction and the direction to the viewer. A fixed sideways axis collapses to nothing for an edge that runs away from the camera (the bag's base ring does exactly that). `DoubleSide` is correct for these, not a papered-over winding bug: which way a billboarded quad faces depends on which side of it you are.
- **`npm run build` does not catch a temporal-dead-zone error.** Vite bundles without evaluating, so a module-level `const` that references another declared further down the file builds clean and throws the moment it runs. Bit us with the bag's edge table referencing `TOP_V`. Importing the module in Node catches it instantly.
- **Judge contact-based rules from cannon's `collide` events, not per-frame sampling.** A contact is created and resolved inside `world.step()`, so by the time a frame ends a bounce has already happened and been smoothed away — sampling positions each frame misses it entirely. `throwIn.js` is the reference example.
- Physics step is fixed at 1/240s (`FIXED_DT` in `physics.js`) because thin items (lip balm, toothbrush) tunnel through 3cm shelf boards at larger steps.

## Testing physics/gameplay changes

**Shortcut: type `chellito` anywhere in the game** (not in a text field) to get a finished bag: it lands on the first free table spot with one free copy of every item sealed in and a gift tag attached, then runs the normal finish → counter → Mia pickup. If the table is full or an item has no free copy it does nothing (console warning) — press Restock. See `cheats.js` / `bags.autoPack()`. Automated browser "typing" doesn't fire keydown here, so in a test script dispatch `KeyboardEvent('keydown', { key, bubbles: true })` on `document.body` instead.

Prefer a **headless Node script** driving `world.step()` directly over browser automation for anything involving the spring/physics loop. Automated browser tabs in this environment are frequently not OS-focused, which means `document.hidden` is true and `requestAnimationFrame` — which the entire game loop runs on — doesn't fire, regardless of how long you wait. Screenshots still render (CDP forces a frame for capture) so visual/UI checks work fine in-browser; anything time-dependent (drag settling, bag snapping, arrow animations) does not, and will silently appear frozen. A minimal DOM stub (`document.createElement` returning a plain object with `style`/`classList`/`addEventListener`) is enough to run `bags.js`/`tags.js`/`softRag.js` headlessly — see prior test scripts in scratch space for the pattern if reconstructing one.

**Headless Edge renders WebGL for a real screenshot**, shaders included, with no browser extension: with the dev server up, `msedge.exe --headless=new --use-angle=swiftshader --enable-unsafe-swiftshader --window-size=1600,900 --virtual-time-budget=8000 --screenshot=out.png http://localhost:5173/` (Edge lives in `C:/Program Files (x86)/Microsoft/Edge/Application/`; add `--enable-logging=stderr --v=0` to see console errors). It is the only check here that catches a shader compile error — `npm run build` doesn't. `--screenshot` can't click, so to get past the menu launch Edge with `--remote-debugging-port=9333` instead and drive it over CDP from Node (Node 24 has `fetch` and `WebSocket` built in): `Page.navigate`, `Runtime.evaluate` to click `.menu-play`, then `Page.captureScreenshot`. Headless tabs count as visible, so `requestAnimationFrame` runs and the bubble intro actually animates.

Two things worth knowing about what else runs headlessly:

- `layout.js` and `physics.js` import cleanly in Node, so item sizes, shelf packing, collider offsets and "does it settle when dropped" are all testable by stepping the world directly.
- **Three.js geometry needs no WebGL context.** `createItemMesh()` and `new THREE.Box3().setFromObject(mesh)` work in plain Node, which makes it cheap to assert that a mesh agrees with its collider — that it rests flush on a shelf rather than floating above or sinking into it, and that it doesn't overhang its own bounds. Only the renderer needs a browser.
- **A camera works headlessly too**, which makes anything view-dependent testable: build the same camera `scene.js` does (FOV 45 at `(0, 1.35, 2.75)` looking at `(0, 0.95, 0)`), call `vector.project(camera)`, and compare screen positions in pixels. That is how the bag's ink was checked against the film's edge.

Traps that have each cost a wrong conclusion:

- **Test at the position the thing actually occupies.** A bag tested at the origin sits symmetrically in front of the camera and hides every off-axis bug; the table is at x=0.95. Same for the outline, which looked correct at x=0 and was 32px out where the bag really lives.
- `Box3.setFromObject()` **caches** `geometry.boundingBox`. After writing new vertex positions it returns stale bounds unless you recompute, so a mesh that is visibly changing shape reports constant size. Scan the position array directly when the geometry is being rebuilt per frame.
- A soft rag's `body` is a **centroid proxy that only refreshes inside `rag.update()`**. A harness that steps the world but skips the rag update sees it frozen at its spawn point, and containment checks silently disagree with where it is.
- The bag generator's `userData.onGrab(point)` supplies **its own** origin — passing one is ignored, and the bag spawns at the shelf. To place a bag, ramp the drag target across rather than jumping it: the cursor spring has a `MAX_STRETCH`, so a target teleported to the table never pulls the bag there. `release()` also vetoes the snap unless the bag's centroid is genuinely over the table.
- Dropping every item into a bag at one point makes them explode apart; stagger the drops and let each settle, as a player would.

## Deploy

GitHub Actions (`.github/workflows/deploy.yml`) builds and deploys to Pages automatically on push to `main`. Live at whatever Pages URL is configured in repo Settings → Pages (Source must be "GitHub Actions", not "Deploy from a branch").
